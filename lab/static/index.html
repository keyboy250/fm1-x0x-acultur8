ARCHIVE REVIEW / FM1-X0X
Codebase notes
01 / ARCHITECTURE
Five parts, one audio engine.
909, 808, 303 A, 303 B and break playback feed shared FX and master processing. Parameter changes are queued from the main loop to the audio ISR. Preserve that ownership boundary when adding controls.
02 / EDITOR PROTOCOL
The docs outgrow this fork.
web/EDITOR_PROTOCOL.md describes Felucca’s parameter, preset and track APIs. X0X’s actual editor.c supports INFO, PING and sample-slot commands, including SMP_READ. A live parameter dashboard requires new firmware protocol work.
03 / SIMULATION
Two paths to a preview.
The host simulator renders the real app to audio and screenshots from .x0x scenarios. The browser emulator is compiled locally from the working firmware and runs in an AudioWorklet. Rebuild after edits; the dashboard flags stale builds. The host simulator provides reference audio and screenshots.
04 / PERSISTENCE
A format change is a migration.
32 patterns, up to 64 steps, song and motion lanes are persisted in project storage. Changes to field order, parameter indices or revisions need old-project readback and save/reboot proof.
05 / INHERITED TESTS
Some tests still target Felucca.
web/test_web.mjs references editor.html and firmware/src/params.c, neither present in this archive. Treat that test as blocked, not as X0X coverage. DSP reference tests also require external source trees.
06 / PROVENANCE
Keep the original within reach.
The ZIP and extracted baseline remain separate from edits. Each save retains the previous file. Exports contain the complete working source, licences, change inventory and recorded checks; they are not flashable firmware.
07 / COMMUNITY RESEARCH · 2026-10-13
Community ideas, checked against sources.
SLOOP documents grids, mixer, samples and backup; Melodee documents its FM6 editor; Baud Girl documents knob banks, grouped menus and color options. Community directory ↗
X0X already has a browser emulator. The supplied Boldport attribution and exact six-row/SELECT HUD details remain unverified. Documentation checks do not establish hardware stability or compatible SysEx.
Deferred proposals FM1-29–31: visual sequence editor, contextual knob/FAQ guide, and firmware-aware backup manager. Existing acceptance work comes first. Full research: dashboard/COMMUNITY_SIDE_NOTES.md. Development remains local until publication sign-off.
