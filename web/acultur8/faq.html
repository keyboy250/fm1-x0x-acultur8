The WAV holds the slices. The markers tell the emulator when each one should play.

What works in this alpha?

The browser instrument, WAV and exact-marker import, individual slice audition, original-timing playback, browser saves and sequencer tempo sync are available. Filters, boost/ceiling strips, arrangement blocks, chord progression and MIDI pad accompaniment are staged development targets.

Follow the quick start or load the public synthetic demo directly from the emulator. The demo's six unequal onsets make changes in groove easy to hear.

Can this website open a raw REX file?

Use the matching WAV slice bank and marker JSON exported by a compatible converter. This static website has no native REX decoder. The local lab supports optional native conversion when its separate decoder is configured. SDK installation and distribution permissions remain separate from this public package.

Why can the WAV be longer than the loop?

The WAV packs each intact slice end to end, including its ringing tail. Marker startSample and endSample locate that sound in the bank. Marker time is its original musical onset in seconds. Adding slice lengths together would lose overlaps and gaps.

How does sync keep the pitch?

Play with FM1 · keep pitch schedules slice starts against the internal sequencer clock. Each slice plays at its original speed. At faster tempos tails overlap more; at slower tempos gaps may appear. This is slice sequencing, rather than continuous stretching of sustained audio.

If stopped, both start from beat one. If already playing, the loop joins the next four-beat bar. Instrument PLAY then stops and restarts both. Original loop length is retained: a 7/8 loop still spans 3.5 quarter-note beats. Enter its source BPM if the markers have none.

Which files belong together?

Choose the _slices.wav and _markers.json from the same export. JSON can carry sample rate, frame count, channels, BPM, loop duration and exact boundaries. Manual import validates the available dimensions. The local converter handoff also validates the WAV checksum.

CSV uses Slice,Start,End,Time in seconds, with an optional final Loop,,,duration row. Legacy Slice,Duration,Total CSV cannot recover the original onsets; re-export from the REX source. A rendered full-loop WAV is different from a packed slice bank.

Where does Save put my work?

Save import in browser stores the WAV and markers in this browser; Reopen saved import retrieves them. The instrument SAVE control stores instrument state separately. A different browser or website address has different storage. Keep your source files as a portable backup.

Does this put samples into my FM1?

This alpha provides browser audition. Device sample storage, firmware image checks, real CPU measurements, save/reboot and physical recovery tests are separate milestones. No Acultur8 hardware installer is included here.

Which release is this?

Browser alpha.1 passed mandatory CI and hosted synthetic import, tempo sync, transport and save/reopen checks. Local font, command/save and DSP candidates remain unreleased; physical-device acceptance is pending.

What is next?

Start with lossless fonts and a combined resource budget, then finish shared commands and versioned saves. The first complete audible checkpoint is one kick strip. After its acceptance, audio expansion and arrangement/harmony can proceed in parallel.

The next complete sound checkpoint is one 909 kick with high-pass, low-pass, boost, ceiling, metering and persistence. Once measured, it expands to other sounds. Arrangement blocks, seven-degree chord progressions, chord-following bass and external MIDI pads follow in the development plan.

When will the next features arrive?

Planning windows from resumed implementation are 4–7 focused days for sound controls and 8–12 for the musical browser alpha. These are conditional forecasts: memory redesign and failed acceptance may extend them. Physical-device qualification has no fixed date.

Why measure memory first?

The unmerged font candidate saves 18,368 flash bytes but leaves RAM unchanged. Sound processing, saved settings, undo and arrangement must fit together within the established resource limits before device qualification.
